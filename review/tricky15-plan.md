# 15 轮审查范围

按 `tricky15-plan.json` 的十五个主题执行，覆盖当前已实现的页面、操作和数据路径。主题与用例有明确对应关系，不把一次检查循环十五遍。当前简约视觉和交互约定继续以 `visual-system.md`、`interaction-components.md` 和用户最后一次同类要求为准。

本次额外验证版本升级：以实际发布过的 `2da26a8` HTML 充当旧页面，与当前构建在同源隔离浏览器中共存，验证旧已读迁移、旧运行页面、旧结果页面、模型改名与结果更新、无效存储恢复。场景不依赖模拟重写旧版函数，不调用模型或设备服务。

沿用维护中的二十组页面路径，并按十五个主题组合；每个路径独立上下文，避免审批、删除或已读等状态污染。所有设备、资产、有效画布节点逐项遍历；按钮按路由、操作和方向统计，禁用类型单列。只有实际点击才计入操作覆盖。实验导出逐份检查 JSON 中的批次编号，并避免过快连续下载触发浏览器限制。

LabOS 六项对齐建议仍待用户确认。本轮在报告单列设备实例、能力节点、方案与运行、样品及资源依赖、取消恢复、数据回流六项待确认内容；不把方案完整性审查写成已实施能力，不向实际设备下发任务，也不根据“执行 15 轮审查”推定业务调整已获批准。

执行入口：`npm run test:tricky15`。输出为 `work/qa/tricky15/` 下的截图、逐轮结果、控件清单、原始日志和 HTML 报告。需求专项在同一构建下重新执行，内部专项与顶层用例分别计数。仅复用测试定义，不复用历史通过结果。
